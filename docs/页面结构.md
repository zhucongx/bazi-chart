# 页面结构

这份文档从 `CLAUDE.md` 拆出来，记录页面各版块的设计、实现细节和改动的来历。改页面时按需查阅对应条目。

- 从上到下：顶部的人物切换和「＋ 添加」（点开是填出生信息的表单），带标注的四柱标题，顶部信息；然后是两张卡片。第一张讲原局，带标签栏，一次显示一页：八字、日主、五行、强弱、十神、格局、喜忌、六亲。第二张是大运流年（`#card-pan`）：上面是大运、流年、流月、流日四行选择器（每行一条横向的带子，放不下就横向滚动；流日在电脑上固定十一列、排三行），每张小卡底下一条喜用分的条；下面是跟着选择器走的标签栏：四柱细盘、干支关系、根和透、计分。前三页都是八列，前四列是选中的流日、流月、流年、大运，后四列是原局；计分一页是一张一行一层的计分表。选择器和这几页原来分在两张卡片里，四排柱子单独占一页，2026-11-14 用户说「结合的不是很好」，就合成一张：柱子去掉，喜用分画在选择器的小卡上。六亲和宫位是原局的最后一页（标签 `#h-lq`「六亲」，那一页是 `#p-lq`，上半六亲表、下半宫位表）。这个先后是照读盘的逻辑排的，2026-11-14 用户提的：先看四柱（「八字」一页只排原局四列，行和四柱细盘相同，用户照排盘软件的基本排盘提的，说「就有这些就行了」），再找日主、看五行多少，再看日主强弱（月令、根、印、透干），再认十神、定格局，然后取喜忌；原局看完，才是带着大运流年的细盘和各柱之间的关系。六亲和宫位是典籍给人事分类的办法，不在这条线上：先合成一页放在原局标签的最后，用户说放在那里也不合适，就挪出标签栏，单独放在页面最下面；2026-11-18 用户指着原局的标签栏问「六亲 · 宫位可以放在上面吗」「应该放在上面吗」，我的意见是应该（两张表只看原局四柱，不跟着选择器变，放在最下面要滚过大运流年才看得到），又挪回原局标签的最后。那一页最上面一句原来写「十神配亲属叫六亲，四柱配亲属叫宫位。它们不在强弱、格局、喜忌这条读盘的线上，所以排在最后一页」，用户说「这句话就不对了吧」：六亲是亲属本身，十神和宫位是配它的两种办法；页面为什么这样排也不用写给读的人看。改成「六亲指父母、兄弟姐妹、配偶、子女这些亲属。典籍里把亲属配到盘上有两种办法：一种照十神配，一种照四柱的位置配，叫宫位」。先选后看：选择器就在标签栏上面，换一年不用上下来回滚。
- 标签栏是 2026-11-14 用户提的：日主、五行、十神这些并列的主题点标签换着看，不要全部平铺，平铺太多。标签是 `#h-名字`（`role="tab"`），对应的那一页是 `#p-名字`。两张卡片各有哪些标签写在 `ui.js` 的 `TABS` 里，换页由 `setTab(卡片, 名字)` 完成，翻到哪一页记在 `sel.tab` 和 localStorage 的 `bz-tabs` 里，读写包在 try/catch 里。焦点在标签上时左右方向键换页。换页时，打开的解释所指的字如果在换下去的那一页里，解释就收起。新增或挪动一页时，`TABS`、模板里的标签、`tools/shot.py` 的 `TABS` 和检查脚本要一起改。内容窄的两页（八字、日主）在电脑上左边是内容、右边是解读（`.split`）；八字一页右边解读下面还有四柱之间的合、冲、刑、害（`renderBz()`，小签和干支关系一页原局的小签相同，2026-11-15 用户要的），关掉解读也并排（`.split.keep`）。两张卡片一开始各显示第一页，`sel.tab` 的默认值要和 `TABS` 的第一项相同。窄屏（560 像素以下）上标签不带图标、间距收到 7 像素，好让原局八个、排盘四个标签在 360 像素以上各排成一行（八个以后窄屏字号 15、间距 7、左右不留边）。「格局」一页是 2026-11-17 加的：格局组合表原来放在十神一页最下面，离最上面的格局参考太远；用户问「这个应该放在日主的标签里吗」，看了单开一页和挪到十神页上面两种改法，选了「单开格局标签」，又问其余几个要不要重新排序，照读盘顺序不用动。
- 一页之内的内容都直接显示，不做把内容收起来的开关。试过「只看出生时的四柱」的入门视图和默认收起的神煞，用户看了以后都不要（「直接显示多好」「多此一举」），2026-11-14 去掉了。并列的主题用标签分开和这个不矛盾：用户不要的是把一个主题里的一部分藏起来。
- 标题里每一柱下面的「年柱」等标注、日干上面的「日主」、其余七个字上面的位置（年干、年支、月干、月支、日支、时干、时支），都是样式生成的（`data-k`、`.dm`、`.gd` 的 `data-g`），不占标题的文字内容。七个位置的小字是 2026-11-18 用户要的（「这上面只标记了日主，别的也写一下吧」）；我先标成了十神，用户说「不是标记十神吧，表日干日支之类的」。
- 顶部信息由 `metaRows()` 生成，分两处放：起运和交运在大运那一行下面（`#meta-yun`），其余的都在标题下面（`#meta`），出生的基本信息排在前面。
- 细盘的列由 `cols()` 给出，`DYN` 是前面外来的列数（4）。各行由 `panRows(列)` 画：四柱细盘一页给 `cols()` 的八列，「八字」一页（`renderBz()`，在 `#bz` 里）只给原局四列 `NATAL`，两页的行完全相同，检查脚本逐格对照。第一行叫「十神」，排盘软件里叫主星。手机上八列每列不到 40 像素，样式里专门收紧过，改细盘时要在手机宽度下看一眼有没有横向溢出。
- 页面自带的人在 `DATA.people` 里，是构建时由 lunar_python 排好的：出生信息、真太阳时、四柱、大运、可选的 `notes`。字段说明在 `tools/gen_data.py` 的开头。
- 生在国外的示例，人物文件写当地钟表时间加 `tz`（当地钟表比世界时快几小时，或 `"lmt"` 当地平太阳时）和 `tzName`，`tools/gen_data.py` 先换成北京时间再排，数据里另存一份当地时间 `localClock`（不叫 `local`：`p.local` 早就用来标记存在浏览器里的人）。页面顶部信息（`metaRows()` 里 `loc` 那一段）的公历一行写当地时间，真太阳时和当地钟表比，经度修正照当地时间的基准经线算，钟表落在哪个时辰也看当地钟表，起运一行的出生年月用当地时间。页面上的添加表单仍然只能填北京时间。
- 使用者在页面上添加或导入的人，只把出生信息存在 localStorage 的 `bz-people` 里，每次打开由 `chart.js` 的 `chartOf(出生信息)` 现排，得到和 `DATA.people` 里同样字段的对象。两者合在一起是 `PEOPLE`。读写 localStorage 都包在 try/catch 里，存不了时页面照常能用并给出提示。导入时先试排一遍，排不出盘的不写进浏览器；带 `tz` 的出生信息（`people/` 下生在国外的人的写法）页面不认，导入时跳过并说明；浏览器里存的人缺编号、编号重复或者和自带的人相同的，读的时候另起编号；浏览器里不合格式的旧记录放在 `REJECTED`，保留原值、持续提示并提供导出入口；添加、导入其他人时一并保存，只有同编号资料校验和试排成功才替换。整份 JSON 损坏或不是数组时放在 `RAW_LOCAL`，不覆盖原文，新资料需另行导出。能读却排不出盘的记在 `BROKEN`，也持续提示。`HOUR_PICK` 是没有原型的对象，编号叫 `constructor`、`toString` 的人也能正常用（审阅报告 R4）。
- `chartOf` 的结果必须和 `tools/gen_data.py` 逐项相同。改其中一个，另一个要一起改，再跑 `tools/fuzz.py`。节气和农历来自 `TABLES`（`data/tables.json`）。
- 四柱用哪一个时间：年柱、月柱看出生的那一刻在交节之前还是之后，拿钟表时间（北京时间）和节气表比；日柱、时柱照当地的真太阳时；大运也按钟表时间，和年柱、月柱接得上。2026-11-17 以前四柱都照真太阳时，交节前后同一个时刻换个经度就换了年柱、月柱，内容审阅指出后用户说改。`gen_data.py` 用 `MixedLunar` 把年、月两柱交给钟表时间那一刻的农历对象。真太阳时落在交节另一边的，顶部信息「节气」一行写明。
- 大运照交运的那一天认（`ui.js` 的 `dyStart()`、`dyAt()`）：每一步从起运日往后推十年。选择器里的大运和流年仍按整年排，「当前」那枚印照今天实际所在的那一步标；选中的日子不在选中的那一步里（交运那一年里交运以前的日子，或者还没起运）时，选择器下面一句说明（`#note-dy`，`text.js` 的 `dyNote()`），细盘的大运一列仍排选中的那一步。今天不在大运范围里的人（古人），默认停在起运的那一天。2026-11-17 内容审阅指出原来只按年份认大运，用户说改。
- 导入的手写解读先由 `cleanNotes` 照 `docs/数据格式.md` 的格式核对形状，不合格式的项丢掉，导入的提示里说明丢了几项；留下的经过 `cleanHTML` 过滤，只留排版用的标签和 `class`，`id` 去掉（只有顶替 `read.yun` 的那一段留 `id="layers"`）。浏览器里以前存下的，`readLocal()` 每次打开也照这个规矩再过一遍。页面自带的 `notes` 是构建时写进去的，不过滤。
- 出生时间只记到时辰的人带 `shichen` 字段（史料里的古人，或者使用者只知道时辰）：取时辰的中点直接当真太阳时，没有钟表时间和经度换算，顶部信息里是「时辰」一行，没有「真太阳时」。页面内排盘只支持 1900 到 2100 年；更早的人只能在构建时由 `tools/gen_data.py` 排好放进页面。
- 时辰不详的人带 `nohour: true`，`birth` 只写日期，只能在页面上添加（`people/` 下的文件不支持）。2026-11-14 用户在几种办法里选了「十二个时辰换着看」：排盘时另给一个时辰，当「只知道时辰」排（`chartOf` 里没给就按午时）；`HOUR_PICK` 按人记着现在看哪个时辰，只记在这一次打开的页面里。标题里的时柱淡一些，标「（不详）」；标题下面一排十二个时辰（`renderHours()`，在 `#hours` 里），点哪个就按哪个重排；下面一段由 `hoursSay()` 生成，说十二个时辰里哪些不变、哪些跟着变（时柱、强弱计分的范围、扶抑取的喜用；交节气的那天月柱也会变，交立春的那天年柱和大运的顺逆也会变；起运的日子照十二个时辰实际排出来的最早和最晚写，交节气那天能差十年上下）。换时辰时，选中的大运、年、月、日能留的都留着（`stayAt()`，画之前先定好位置，只画一遍）。没有选只排三柱，是因为强弱计分和书里的两条线都是照四柱定的，三柱用不上。
- 2026-11-18 用户让「全面检查项目，文档，待办，内容，排版，代码，排盘方法等」，分五路审阅（代码、页面文字、排盘方法、文档、排版），逐条核实以后改的。往后要记住的几条：
  - 点开的解释只写这一条自己的内容。每一条都一样的话（怎么查、注意、名词以外的通用说明）放在表下面的说明里说一次：成败救应、格局组合、调候的情形、关系图的生克小圈都照这个改了。这和用户早先说小卡明细「每根柱子都一样的话是重复」是同一个意思。
  - 喜神、忌神、仇神落在哪一行，用神有余和不足不一样（`yongShen()`）。含义由 `ysHuman(名目, 有余还是不足)` 照这张盘写，不写一句通用的定义：原来写「忌神是克用神的那一行」，用神不足的盘上和「这张盘」一段正相反。
  - 十神、五行的传统读法出现在「含义」里时，写「照传统的读法」「传统上读作」，不写成事实。
  - 出处是一整段话，不往句子中间拼。页脚和时柱的解释原来写「某某上的钟表时间是」，出处长了读不通；现在出处单独一句。生在国外的人写当地时间。
  - 只知道时辰、交节又落在这个时辰前后三小时以内的人，年柱、月柱和大运的顺逆定不了，「节气」一行多一段「只知道时辰」说明，写出另一边排出来的月柱。
  - 合化改记的字要交代：强弱计分的「拆开看」、强弱分析卡片四块的解释，日主自己那一笔和本来帮日主的字改记走了，都写出来，不然分数加不起来、和得地卡片对不上。
  - `infoFrom()` 从排好的人取回出生信息时把夏令时的一小时加回去、照样标 `dst`；检查脚本拿它再排一遍，这样才走得到 `chartOf` 的夏令时分支。
  - `xiOf()`、`yongOf()` 现在每张盘都给结果（全部 518400 种四柱组合核对过），代码里「不定」的分支走不到了，还留着没有删。
  - 排版上改的：圈里和字块里的字都往上托字号的百分之五（关系图、根和透、五行图、细盘的干支大字、强弱卡片的日主）；流日小卡在 900 到 1059 宽星期只留一个字；原局八个标签在 719 宽以下不带图标、900 到 979 宽间距收到 26，360 宽以上都排成一行；十神图占 480 像素只在 1100 宽以上；强弱四张卡片 560 到 1059 宽两张一排；电脑上流年、流月的小卡可以缩；水的淡底加深一档，垫在灰底上才看得出；五行表的月令状态（`wst|五行序号`）和格局两张表里的小签都做成能点的；夹在文字里的可点词都带虚线下划线，不是按钮的可点元素焦点框和按钮一样。
