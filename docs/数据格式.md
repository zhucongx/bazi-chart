# 数据格式

这份文件讲页面读写的几种数据：出生信息、分享链接、手写的解读、人工核对过的事实。

页面自带的示例人物放在 `people/`，每个人最多三个文件：

| 文件 | 内容 | 能不能没有 |
|---|---|---|
| `<id>.json` | 出生信息 | 必须有 |
| `<id>.notes.json` | 手写的解读 | 可以没有 |
| `<id>.facts.json` | 人工核对过的事实，检查脚本拿它对照页面 | 可以没有 |

使用者自己添加或导入的人物（可附带 `notes` 字段保存手写解读）只存在浏览器的 `localStorage` 里，通过页面表单里的「导入文件」「导出」读写。

## 出生信息

```json
{
  "id": "me",
  "name": "我",
  "gender": "男",
  "birth": "2000-01-01 12:00",
  "place": "北京市",
  "lon": 116.4,
  "order": 1
}
```

出生时间有三种记法：

| 记法 | `birth` 写什么 | 另外写什么 | 怎么排 |
|---|---|---|---|
| 按出生时间 | 北京时间的钟表时间 | `lon`：出生地的东经度数 | 年柱、月柱照钟表时间，日柱、时柱照换算出来的真太阳时 |
| 只知道时辰 | 只写日期 | `"shichen": "巳"`，不写 `lon` | 取这个时辰的中点来排 |
| 时辰不详 | 只写日期 | `"nohour": true`，不写 `shichen` 和 `lon` | 页面按选中的时辰排，默认午时 |

- `lon` 用来换算真太阳时。西经写负数，范围是 −180 到 180。在国外出生的：在页面上添加的人，`birth` 要先换算成北京时间；`people/` 下的文件可以直接写当地时间，另外写 `tz`（见下面的可选字段）。
- 时辰不详的只有在页面上添加的人才有，会出现在浏览器里存的出生信息和导出的文件里。`people/` 下的文件不支持这个字段。
- 人物按 `order` 排序。

可选的字段：

| 字段 | 意思 |
|---|---|
| `"dst": true` | 出生时间是夏令时，排盘时先减一小时 |
| `"tz": -8` 或 `"tz": "lmt"` | 只用于 `people/` 下的文件。`birth` 写的是当地的钟表时间，`tz` 是当地钟表比世界时快几小时（西边是负数，夏令时直接算进去），`"lmt"` 表示按出生地经度定的当地平太阳时。排盘时先换成北京时间；页面顶部信息写当地时间。写了 `tz` 就不写 `dst` 和 `shichen` |
| `"tzName"` | 当地时间的名字，比如「太平洋标准时间」，显示在页面上 |
| `"jie": "before"` 或 `"after"` | 只和 `shichen` 一起用，只用于页面上添加的人。交节正落在这个时辰里时，说明出生在交节之前还是之后，年柱、月柱和大运照这一边排。和时辰中点所在的一边相同，或者这个时辰里没有交节的，写了也不起作用。`people/` 下的文件不支持 |
| `"source"` | 出生时间的来源，会显示在页面上 |
| `"memo"` | 给自己看的备注，不进页面 |
| `"expect": ["年柱", "月柱", "日柱", "时柱"]` | 排出来的四柱必须等于它 |
| `"expectYunStart": "YYYY-MM-DD"` | 起运日期必须等于它 |
| `"expectTst": "YYYY-MM-DD HH:MM:SS"` | 真太阳时必须等于它 |
| `"expectLunar": "甲午年三月十八"` | 农历必须等于它 |

`expect` 开头的几项，对不上时生成数据会报错退出。

在页面的表单里点「导入文件」，可以直接读这样的文件，一个人或者几个人的数组都可以。带 `tz` 的文件页面不能导入（页面里的排盘只认北京时间），导入时会跳过并说明；要先把出生时间换成北京时间、去掉 `tz`。`people/` 下的文件必须有 `id`、`name`、`gender`、`birth`、`place`、`order` 六项，缺了生成数据时报错退出；页面导入必须有 `gender`、`birth`；钟表时间还需 `lon`，只知道时辰需 `shichen`，时辰不详需 `nohour: true`。`lon` 要写成数字，或者写着数字的一段文字；`null`、空的文字、`true`、`false` 都不认，这样的人不导入（原来会当成 0 度排出另一副日柱、时柱）。出生地正好在 0 度的写 `0`。缺少 `id` 时生成编号，缺少 `name` 时用「未命名」。导入时可以带上 `"notes"`，内容就是下面说的手写解读。

浏览器里已有的异常记录不会悄悄删除：打开页面会提示原因，并提供「导出保留的原数据」。添加、导入其他人时仍保留这些原值，普通导出也包含它们。修正后以同一 `id` 导入，只有试排成功才替换异常项；没有编号的旧记录需在导出的备份中人工整理。若整份存储内容已不是有效的 JSON 数组，保留原文并暂停覆盖，新加资料只能在本次打开时使用，需要另行导出。

同一个浏览器开着两个标签页时，各自添加、修改、删除的人互不覆盖：保存前先读一遍浏览器里现在存的，只把这个标签页自己动过的人写进去；另一个标签页存了以后，这一页的人物那一排跟着更新。两页同时改同一个人的，后保存的为准。

## 分享链接

页面上的「分享」把一个人写成一个链接，出生信息放在网址 `#` 后面。

- 浏览器不会把 `#` 后面这一段发给服务器，但拿到链接的人都看得到。
- 链接一律指向公开的页面 <https://zhucongx.github.io/bazi-chart/>。
- 浏览器复制出来的链接里，中文和逗号会写成 `%E5%B0%8F` 这样的形式，意思一样。

下面的例子都是虚构的：

```
https://zhucongx.github.io/bazi-chart/#n=小王&g=f&b=1985-03-12T09:30&lon=121.5&tab=qr,sy&dy=3&y=2026
https://zhucongx.github.io/bazi-chart/#n=小李&g=m&b=2003-06-18&sh=卯
https://zhucongx.github.io/bazi-chart/#n=小赵&g=f&b=1959-09-09&nh=1&h=子
https://zhucongx.github.io/bazi-chart/#n=小钱&g=m&bz=癸未戊午乙卯己卯
```

### 出生信息，几种写法选一种

| 写法 | 参数 |
|---|---|
| 按出生时间 | `b` 写到分钟（`YYYY-MM-DDTHH:MM`，有秒的可以再加 `:SS`）；`lon` 是出生地的东经度数；夏令时另写 `dst=1` |
| 只知道时辰 | `b` 只写日期；`sh` 是时辰，子到亥，一个字。出生信息里记着交节前后（`jie`）的，另写 `jq=a`（交节之后）或 `jq=b`（交节之前） |
| 时辰不详 | `b` 只写日期；写 `nh=1`，不写 `sh`。分享时另带 `h`，是分享的人正在看的那个时辰，打开时照它排；不写就按午时排 |
| 直接给八字 | `bz` 是四柱八个字。打开时在 1900 到 2100 年里找四柱都对得上的日子，取最早的一天；`b` 可以指定是其中哪一天。对得上的日子不止一个时，打开以后可以换。对得上的日子在交节另一边的（交节落在那个时辰里），页面自己照那一边排 |

页面自带的人，在页面里能排的（1900 到 2100 年出生）也照上面写出生信息；更早的只写编号，比如 `#p=chiang-kai-shek`，只在页面自带这一位时打得开。

### 别的参数

| 参数 | 意思 |
|---|---|
| `n` | 称呼，最多 20 个字，只当文字显示 |
| `g` | 性别：`m` 男，`f` 女 |
| `p` | 页面自带的人的编号，见上面 |

下面几项是打开以后停在哪里，都可以不写：

| 参数 | 意思 |
|---|---|
| `tab` | 标签的名字，几个用逗号隔开：`bz`、`tk`、`wx`、`qr`、`gods`、`gj`、`ys`、`lq`、`pan`、`rel`、`gt`、`sy` |
| `dy` | 第几步大运，从 0 数 |
| `y` | 年份，会换到那一年所在的大运 |
| `m` | 第几个月，从立春那个月数，从 0 数 |
| `d` | 日期，`YYYY-MM-DD` |
| `h` | 时辰不详的人正在看的时辰，见上面 |
| `by` | 四个设置，逗号隔开：五行数法（`face`、`cnt`、`nl`）、十神数法（`face`、`cnt`、`nl`）、小卡计分（`fy`、`ys`、`sum`）、格局子标签（`gjb` 成败救应、`gjz` 格局组合）。打开时恢复设置和可见表格；认不出的值不动，只有前三项的旧链接保留当前格局子标签，没有 `by` 的链接保留全部原设置 |

### 打开链接时

- 每一项都照添加表单的规矩核对（`checkInfo`）。不对的不打开，在人物那一排下面说明原因。
- 打开的人先标「来自链接」，不存进浏览器；点「保存到这个浏览器」才存，存完清掉网址里的 `#`，刷新不再重走一遍链接。
- 链接里的 `tab` 和 `by` 只对这一次打开生效，不覆盖用户自己存在浏览器里的标签和数法偏好。
- 出生信息和已经有的某一位完全相同时，直接换到那一位。

## 手写的解读

页面上的解读包括干支的机械事实，以及注明典籍和规则的强弱、格局、调候等归类；不据此对具体人生作判断。想给某张盘加上自己写的解读，写在 `<id>.notes.json` 里。五项都可以不写：

```json
{
  "read": { "pan": "<p class=\"rd-h\">解读 · 这张表怎么读</p><p>……</p>" },
  "x": { "g|年|己": [["你的盘", "……"]] },
  "rel": { "相冲子午": "……" },
  "meta": [{ "k": "月令司令", "after": "空亡", "dd": "……", "t": "标题", "p": [["是什么", "……"]] }],
  "kv": [{ "k": "我的笔记", "after": "调候参考", "dd": "……", "t": "标题", "p": [["是什么", "……"]] }]
}
```

| 键 | 格式 | 作用 |
|---|---|---|
| `read` | 对象：页面的名字对一段 HTML | 整个顶替某一页的解读框 |
| `x` | 对象：页面元素上的 `data-x` 对段落的数组 | 给某一条解释加段落 |
| `rel` | 对象：关系的类型加上涉及的字，对一段 HTML | 给原局的某一条干支关系加一段 |
| `meta` | 数组，一项是一行 | 在顶部信息里加行 |
| `kv` | 数组，一项是一行 | 在原局各页的列表里加行 |

### read：顶替解读框

可用的名字：

| 名字 | 哪个解读框 |
|---|---|
| `bz` | 八字 |
| `pan` | 四柱细盘 |
| `yun` | 选中的四层 |
| `rel` | 原局的关系 |
| `rel2` | 关系怎么读 |
| `wx` | 五行 |
| `tk` | 日主 |
| `qr` | 强弱 |
| `gods` | 十神 |
| `gj` | 格局 |
| `ys` | 喜忌 |
| `lq` | 六亲 |
| `gw` | 宫位 |
| `gt` | 根和透 |
| `tr` | 计分一页讲小卡底下的条 |

顶替 `yun` 时要保留 `<dl class="layers" id="layers"></dl>`，选中的四层画在里面。

### x：给解释加段落

- 每个段落是 `[标题, 文字]`，也可以写成 `[标题, 文字, 要顶替的段落标题]`。
- 标题是「你的盘」的段落，顶替生成的「这张盘」。
- 标题和原有段落相同的，顶替原段落。其余的加在后面。
- 页面上第一段一律显示成「含义」。要顶替第一段，标题写「含义」，或者照旧写「是什么」「意思」，都可以。

### meta 和 kv：加行

- 一行写成 `{k: 行名, after: 插在哪一行后面, dd: 显示的值, t: 解释的标题, p: 解释的段落}`。
- 行名和页面生成的某一行相同时（比如「调候参考」），手写的在原来的位置顶替生成的，这时 `after` 不起作用。手写的没有「典籍」一段时，生成的那一段原文会留下。
- `kv` 的行跟着它插在哪一行后面（`after`）进哪一页：

| 插在哪几行后面 | 进哪一页 |
|---|---|
| 日主、阴阳、月令、根、印、月令透干 | 「强弱」一页，强弱分析卡片的下面，和「月令透干」排在一起 |
| 强弱参考、打分法、强弱计分、从格、合化 | 「强弱」一页，得令、得地、得势、得气四张卡片的下面 |
| 格局参考、用神变化、相神 | 「格局」一页 |
| 调候参考、三行对照，或者没写 `after` | 「喜忌」一页 |

页面生成的各行，先后是：日主、阴阳、月令、根、印、月令透干、强弱参考、打分法、强弱计分、从格、合化、格局参考、用神变化、相神、调候参考、三行对照。其中日主、阴阳、月令、根、印、强弱计分六行不在列表里单独显示，画在别处（「日主」一页的四项、「强弱」一页的卡片），但仍然可以拿来当 `after`。

### 导入时怎么核对

- 先照上面的格式核对形状：`read`、`x`、`rel` 是对象；`meta`、`kv` 是数组；段落是 `[标题, 文字]`，也可以再加一项要顶替的标题；`read` 的名字是上面列的那些；顶替 `yun` 的里面有 `id="layers"`。
- 不合格式的项丢掉，导入的提示里说明丢了几项。
- 留下的只保留排版用的标签和 `class`，脚本一类的内容会被去掉。`id` 也去掉，只有顶替 `yun` 的那一段留 `id="layers"`。
- 浏览器里以前存下的手写解读，每次打开页面也照这个规矩再过一遍。

## 核对过的事实

`<id>.facts.json` 里记的是从别处核对过的结果，比如对照别的排盘软件抄下来的。检查脚本逐项拿它对照页面，对不上就报失败。每一项都可以不写：

```json
{
  "title": "四柱连写的八个字",
  "rows": { "主星": ["年", "月", "日", "时"], "纳音": ["…", "…", "…", "…"] },
  "dayun": ["八步大运的干支"],
  "bars": ["五行一栏每行的个数：含藏干数，括号里是只数盘面八个字的个数，比如 2 个（1）"],
  "shensha": [["年柱的神煞"], ["月柱的"], ["日柱的"], ["时柱的"]],
  "meta": { "农历": "这一行里应当出现的文字" },
  "rel": { "rel-ng": ["原局天干的关系，类型加字"], "rel-nz": ["原局地支的关系"] },
  "steps": [{ "dy": 2, "y": 2026, "cols": ["流年的干支", "大运的干支"], "eq": {}, "has": { "rel-ln": ["这一年带来的关系里应当有的"] } }]
}
```

| 键 | 意思 |
|---|---|
| `title` | 四柱连写的八个字 |
| `rows` | 键是细盘的行名，值是原局四柱那四格的文字 |
| `dayun` | 八步大运的干支 |
| `bars` | 五行一栏每行的个数 |
| `shensha` | 年、月、日、时四柱各自的神煞 |
| `meta` | 顶部信息：行名对这一行里应当出现的文字 |
| `rel` | 原局的关系：`rel-ng` 是天干的，`rel-nz` 是地支的，写类型加字 |
| `steps` | 选中第几步大运、哪一年之后应当看到什么 |

- 事实文件多半是照排盘软件抄的，那里把天干的十神一行叫「主星」。页面上这一行叫「十神」，检查脚本会把「主星」对到它上面。
- `steps` 里：`dy` 是大运的序号，从 0 起；`y` 是年份；`eq` 要求某一组关系恰好等于给出的，`has` 只要求包含。
