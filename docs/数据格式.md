# 数据格式

每个人最多三个文件，放在同一个目录里：

- `<id>.json`：出生信息。
- `<id>.notes.json`：手写的解读，可以没有。
- `<id>.facts.json`：人工核对过的事实，可以没有。检查脚本拿它对照页面。

页面自带的历史人物放在 `people/`。个人的放在 `private/people/`，这个目录不入库。

## 出生信息

```json
{
  "id": "me",
  "name": "我",
  "gender": "男",
  "birth": "2000-01-01 12:00",
  "place": "北京市",
  "lon": 116.4,
  "order": 1
}
```

- `birth` 是北京时间的钟表时间。`lon` 是出生地的东经度数，用来换算真太阳时。
- 只知道时辰的，`birth` 只写日期，另外写 `"shichen": "巳"`，不用写 `lon`。这时取这个时辰的中点来排。
- 人物按 `order` 排序。
- 可选的字段：
  - `"dst": true`：出生时间是夏令时，排盘时先减一小时。
  - `"source"`：出生时间的来源，会显示在页面上。
  - `"memo"`：给自己看的备注，不进页面。
  - `"expect": ["年柱", "月柱", "日柱", "时柱"]`、`"expectYunStart": "YYYY-MM-DD"`、`"expectTst": "YYYY-MM-DD HH:MM:SS"`、`"expectLunar": "甲午年三月十八"`：排出来的四柱、起运日期、真太阳时、农历必须等于它，否则生成数据时报错退出。

在页面的表单里点「导入文件」，可以直接读这样的文件，一个人或者几个人的数组都可以。导入时可以带上 `"notes"`，内容就是下面说的手写解读。

## 手写的解读

页面上的解读是按干支生成的，只讲机械的事实，不下判断。想给某张盘加上自己写的解读，写在 `<id>.notes.json` 里：

```json
{
  "read": { "pan": "<p class=\"rd-h\">解读 · 这张表怎么读</p><p>……</p>" },
  "x": { "g|年|己": [["你的盘", "……"]] },
  "rel": { "相冲子午": "……" },
  "meta": [{ "k": "月令司令", "after": "节气", "dd": "……", "t": "标题", "p": [["是什么", "……"]] }],
  "kv": [{ "k": "调候参考", "after": "印", "dd": "……", "t": "标题", "p": [["是什么", "……"]] }]
}
```

- `read`：整个顶替某个版块的解读框。可用的名字是 `pan`、`yun`、`rel`、`rel2`、`wx`、`tk`、`gods`。顶替 `yun` 时要保留 `<dl class="layers" id="layers"></dl>`。
- `x`：给某一条解释加段落。键是页面元素上的 `data-x`。标题是「你的盘」的段落会顶替生成的「这张盘」，标题相同的顶替原段落，其余的加在后面。
- `rel`：给原局的某一条干支关系加一段，键是类型加上涉及的字。
- `meta`、`kv`：在顶部信息和日主一栏里加行。行名和页面生成的某一行相同时（比如「调候参考」），手写的顶替生成的；手写的没有「典籍」一段时，生成的那一段原文会留下。
- 导入时，手写解读里只保留排版用的标签，脚本一类的内容会被去掉。

## 核对过的事实

`<id>.facts.json` 里记的是从别处核对过的结果，比如对照别的排盘软件抄下来的。检查脚本逐项拿它对照页面，对不上就报失败。每一项都可以不写：

```json
{
  "title": "四柱连写的八个字",
  "rows": { "主星": ["年", "月", "日", "时"], "纳音": ["…", "…", "…", "…"] },
  "dayun": ["八步大运的干支"],
  "bars": ["五行一栏每行的个数文字"],
  "shensha": [["年柱的神煞"], ["月柱的"], ["日柱的"], ["时柱的"]],
  "meta": { "农历": "这一行里应当出现的文字" },
  "rel": { "rel-ng": ["原局天干的关系，类型加字"], "rel-nz": ["原局地支的关系"] },
  "steps": [{ "dy": 2, "y": 2026, "cols": ["流年的干支", "大运的干支"], "eq": {}, "has": { "rel-ln": ["这一年带来的关系里应当有的"] } }]
}
```

- `rows` 的键是细盘的行名，值是原局四柱那四格的文字。
- `steps` 是「选中第几步大运、哪一年之后」应当看到什么：`dy` 是大运的序号（从 0 起），`eq` 要求某一组关系恰好等于给出的，`has` 只要求包含。

## 个人页面

把文件放在 `private/people/` 里，然后：

```bash
.venv/bin/python tools/gen_data.py --private
python3 tools/build.py --private && node tests/check_page.js --private
open private/build/index.html
```

生成的东西都在 `private/build/` 里，随时可以整个删掉。这样得到的页面自带这些人和解读，不依赖浏览器里保存的数据。`private/build/data/people.json` 也可以用「导入文件」读进在线的页面。
